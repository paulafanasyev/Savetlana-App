# Приватность

## Принцип (spec §34, §82, §16)

Не собирать данные просто потому, что это технически возможно. Каждое использование имеет основание.

## Privacy Center

`/privacy` — «Что Светлана знает обо мне»

Пользователь видит и управляет:
- Персонализация
- AI-рекомендации
- История просмотров
- Использование истории покупок
- Подключение VK
- Граф связей
- Контекст подарков
- Аналитика
- Cookies

Кнопки: **удалить**, **экспортировать**, **отключить**, **отозвать доступ**.

## Память (spec §29)

`domains/memory.ts` — структурированная память:

| Тип | Пример |
|------|--------|
| `FACT` | «размер обуви 42» (добровольно) |
| `INFERENCE` | «предпочитает лёгкие ноутбуки» — **с confidence и источником** |
| `PREFERENCE` | «бюджет до 50 000» |
| `TEMPORARY_CONTEXT` | «ищет подарок к 8 марта» |

Каждое `INFERENCE` имеет confidence и источник. Память редактируемая, удаляемая, экспортируемая, consent-aware.

API: `/api/memory` (list, edit), `/api/memory/[id]` (delete).

## Защита от утечки в AI (spec §83–§85)

```
Запрос → Data Classification → PII Detection → Secret Detection
       → Policy Engine → Minimization/Redaction → AI Provider
```

Обнаруживаются: карты, Stripe-ключи (`sk_live_`, `sk_test_`), Bearer-токены, JWT, api keys, email, паспорта, СНИЛС, ИНН.

**Провайдер не видит всю базу.** Для поиска товара не передаются платёжные реквизиты, полный профиль или история всех покупок — только context window конкретной задачи.

Тест: `tests/privacy.test.ts` (7 тестов на детекцию и redaction).

## Запрет на обучение (spec §22, §31)

**Никогда** автоматически не отправляется в обучение:
- пароли;
- платёжные реквизиты;
- секреты;
- токены;
- персональные данные без правового основания;
- закрытые документы;
- приватные сообщения;
- данные социальных сетей сверх разрешённого.

CRM-секреты и приватные пользовательские данные **не становятся весами модели**.

Агент не может менять собственные model weights. Не делается uncontrolled self-modification.

## Consent (spec §31, §35)

Отдельно оформляются:
- персональные данные
- социальные интеграции
- маркетинговые уведомления
- AI personalization
- память
- дополнительные сервисы

## Cookies / аналитика (spec §35)

Consent-aware. Разделяются:
- strictly necessary
- analytics
- personalization
- advertising/marketing

Персональные данные не используются для дополнительных целей без основания.

## Связи (spec §16, §18)

AI **не утверждает** родственную или дружескую связь как факт без основания. Только `VERIFIED` после взаимного подтверждения.

## Антиспам (spec §110)

Светлана не:
- постоянно рекламирует;
- отправляет ненужные уведомления;
- создаёт искусственный urgency;
- скрывает коммерческую заинтересованность;
- выдаёт рекламу за нейтральную рекомендацию.

## Реклама vs рекомендации (spec §111)

Разделяются: `Organic recommendation`, `Sponsored placement`, `Advertisement`. Пользователь понимает, когда результат коммерчески продвигается.
